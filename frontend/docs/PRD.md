# Local LLM Chat — PRD

> 상태: 확정 (v1.0) · 프론트엔드 코드 구현 전 · 기준 자료: `chat_ui_설계도.png`, `backend/schema.py`, `backend/main.py`

## 1. 목적 및 배경

Local LLM Chat은 React 프론트엔드와 FastAPI 백엔드를 통해 로컬에 설치된 Ollama 기반 LLM과 대화할 수 있는 웹 채팅 애플리케이션이다. 외부 클라우드 API에 데이터를 전송하지 않고 로컬 환경에서 모델을 구동함으로써 민감한 데이터의 외부 유출 없이, 그리고 인터넷 연결 여부와 무관하게 AI 채팅 기능을 사용할 수 있도록 하는 것을 목적으로 한다. 사용자는 화면 좌측 패널에서 모델, 시스템 프롬프트, 생성 파라미터(Temperature, Top P, Num Predict 등)를 직접 조정하며 우측 채팅 영역에서 대화를 진행할 수 있다.

## 2. 사용자 시나리오

- **로컬 AI를 실험/학습하려는 개발자·학생**: 여러 Ollama 모델과 파라미터 조합을 바꿔가며 응답 품질 차이를 확인하고 싶어함.
- **민감 정보를 다루는 사용자**: 사내 문서, 개인정보 등을 외부 클라우드로 보내지 않고 로컬에서 AI에게 질의하고 싶어함.
- **오프라인/저지연 환경 사용자**: 인터넷 연결이 불안정하거나 없는 환경에서도 AI 어시스턴트를 사용하고 싶어함.
- **특정 역할의 AI 어시스턴트가 필요한 사용자**: 시스템 프롬프트를 커스터마이징해 "초보자를 돕는 강사" 같은 특정 페르소나로 AI를 활용하고 싶어함.

## 4. 사용자 인터랙션 플로우

1. **메시지 전송**
   - 사용자가 입력창에 텍스트를 입력하면 전송 버튼이 활성화된다(추정).
   - 전송 버튼 클릭 또는 Enter 입력 시 메시지가 채팅 리스트에 사용자 메시지(우측, 파란색 말풍선)로 추가된다.
   - Shift+Enter 입력 시 줄바꿈만 되고 전송되지 않는다.
   - 전송 후 백엔드 응답을 기다리는 동안, AI 말풍선 위치에 타이핑 인디케이터(점 3개 바운스 애니메이션)를 표시한다. 응답 대기 중에는 입력창과 전송 버튼을 비활성화해 중복 전송을 막는다.
   - 응답 수신 후 AI 메시지(좌측, 흰색/회색 말풍선)가 채팅 리스트에 추가된다.

2. **대화 초기화**
   - "대화 초기화" 버튼 클릭 시 현재까지의 채팅 메시지 리스트가 모두 삭제되고 빈 대화 상태로 돌아간다(추정).
   - 클릭 시 확인(confirm) 다이얼로그를 노출해 실수로 인한 대화 손실을 방지한다("대화 내용을 모두 삭제하시겠습니까?" 형태). 확인 시에만 초기화 진행.

3. **파라미터 변경 (모델/시스템 프롬프트/Temperature/Top P/Num Predict)**
   - 좌측 패널에서 값 변경 시 즉시 화면에 반영되며(슬라이더 라벨의 숫자 갱신 등), 별도의 "저장" 버튼 없이 다음 메시지 전송부터 변경된 파라미터가 적용되는 것으로 추정.
   - 파라미터 변경은 기존 대화 내용(채팅 리스트)에 영향을 주지 않는다. 변경 시점 이후의 다음 메시지 전송부터만 새 값이 적용된다.

## 5. 데이터 흐름

개괄 흐름은 확정되었으며, 요청/응답 JSON의 상세 필드 스펙은 다음 단계(기술 스펙 문서)에서 구체화한다.

1. 사용자가 좌측 패널에서 모델/시스템 프롬프트/Temperature/Top P/Num Predict를 설정하고, 채팅 입력창에 메시지를 입력해 전송한다.
2. 프론트엔드가 위 값들을 담아 백엔드 `POST /chat`으로 요청을 보낸다. (요청 필드는 `backend/schema.py`의 `ChatRequest`와 1:1 대응: `message`, `model`, `system_prompt`, `temperature`, `top_p`, `num_predict`)
3. 백엔드가 Ollama에 질의하고, 완성된 응답을 `ChatResponse`(`model`, `message`, `elapsed_time`) 형태로 반환한다.
4. 프론트엔드는 응답을 AI 말풍선으로 렌더링한다.
5. 모델 드롭다운은 최초 진입 시 및 새로고침 아이콘 클릭 시 백엔드 `GET /models`를 호출해 옵션을 채운다.

## 6. 비기능 요구사항

- **에러 처리**: 백엔드/Ollama 연결 실패, 모델 응답 오류(HTTP 500 등) 발생 시, 채팅 리스트 안에 AI 말풍선과 구분되는 인라인 시스템 메시지(빨간 톤 배경/테두리)로 오류 내용을 표시한다. 별도 모달/토스트는 사용하지 않는다(포트폴리오용 데모 흐름을 방해하지 않기 위함). 오류 발생 후에도 입력창은 다시 활성화되어 재시도 가능해야 한다.
- **로딩 상태 표시**: AI 응답 생성 중에는 AI 말풍선 위치에 타이핑 인디케이터(점 3개 애니메이션)를 표시한다. 백엔드가 스트리밍이 아닌 완성된 JSON(`ChatResponse`)을 한 번에 반환하므로(타이핑 효과 아님), 응답 수신 즉시 인디케이터를 전체 메시지로 교체한다.
- **반응형 여부**: 데스크톱 전용으로 확정. 좌측 고정 패널 + 우측 채팅 영역 2단 레이아웃만 지원하며, 모바일/태블릿 대응은 이번 범위에서 제외한다(§7 제외 범위에 명시).
- **접근성**: 별도 명시 없음 — 이번 단계 범위 외로 둔다(향후 개선 항목).
- **성능**: 백엔드가 Ollama 응답을 스트리밍이 아닌 완성된 형태로 반환하므로, 프론트는 응답 대기 시간을 타이핑 인디케이터로만 커버한다. 스트리밍 응답 지원은 이번 범위에서 제외.

## 7. 명시적 제외 범위 (Out of scope)

- 다중 대화(세션/스레드) 저장 및 전환 기능
- 대화 히스토리의 영구 저장(새로고침 후 유지) 및 DB 연동
- 사용자 인증/로그인, 다중 사용자 지원
- 파일 업로드, 이미지 입력 등 멀티모달 입력
- 다국어(i18n) UI 지원
- 다크 모드 등 테마 전환 기능
- 모델 다운로드/설치, Ollama 모델 관리 기능(모델은 이미 설치되어 있다고 가정, 목록 새로고침만 지원)
- 대화 내용 내보내기(export)/공유 기능
- 모바일/태블릿 반응형 레이아웃 (데스크톱 전용)
- 스트리밍(타이핑 효과) 방식의 AI 응답 표시

## 확정된 결정 사항 (기존 "확인 필요" 항목 결론)

프로젝트 목적(**포트폴리오/데모용**, **데스크톱 전용**, 초기화 버튼 옆 아이콘은 **모델 목록 새로고침 용도**)과 이미 구현된 백엔드 코드(`backend/schema.py`, `backend/main.py`)를 근거로 아래와 같이 확정한다.

1. **모델 선택 드롭다운 옵션 목록** → 하드코딩하지 않는다. 프론트가 `GET /models`를 호출해 `ollama list` 결과를 그대로 옵션으로 렌더링한다. (근거: `backend/main.py`에 이미 `/models` 엔드포인트 구현됨)
2. **시스템 프롬프트 텍스트** → placeholder가 아닌 고정 기본값. 백엔드 `ChatRequest.system_prompt` 기본값("너는 초보자를 돕는 친절한 AI 강사다.")과 동일하게 맞춘다. 사용자가 자유 수정 가능.
3. **Temperature min/max/step** → `0 ~ 2`, step `0.1` (근거: `schema.py`의 `ge=0.0, le=2.0`). 기본값은 백엔드와 통일해 `0.6`.
4. **Top P min/max/step** → `0 ~ 1`, step `0.05` (근거: `schema.py`의 `ge=0.0, le=1.0`). 기본값은 백엔드와 통일해 `0.7`.
5. **Num Predict min/max/step** → `1 ~ 2048`, step `1`, 단위는 토큰 수 (근거: `schema.py`의 `ge=1, le=2048`).
6. **빨간 원형 아이콘 버튼** → 모델 목록 새로고침 버튼. `GET /models`를 재호출해 드롭다운을 갱신한다.
7. **전송 버튼 활성화 조건** → 입력값이 공백이 아니고, AI 응답 대기(로딩) 중이 아닐 때만 활성화.
8. **AI 응답 표시 방식** → 스트리밍 아님. 백엔드가 완성된 JSON(`ChatResponse`)을 한 번에 반환하므로 전체 응답을 한 번에 표시한다.
9. **로딩 상태 UI** → AI 말풍선 위치에 타이핑 인디케이터(점 3개 바운스 애니메이션) 표시, 응답 도착 시 실제 메시지로 교체.
10. **에러 UI** → 채팅 리스트 내 인라인 시스템 메시지(빨간 톤)로 표시. 모달/토스트 사용 안 함.
11. **초기화 확인 절차** → confirm 다이얼로그 노출 후 사용자가 확인해야 초기화 진행 (포트폴리오용 데모에서 실수로 대화가 날아가는 것을 방지).
12. **반응형(모바일) 지원** → 미지원. 데스크톱 전용 2단 레이아웃만 구현하며, §7 제외 범위에 반영.
