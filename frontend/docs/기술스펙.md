# Local LLM Chat — 프론트엔드 기술 스펙 (v1.0)

> 기준 문서: `PRD.md` (v1.0) · 기준 코드: `backend/schema.py`, `backend/main.py`, `backend/ollama_chat.py`
> 상태: 확정 · 코드 구현 전 (설계만 포함, 실제 코드는 다음 단계에서 작성)

> **Context7 MCP 사용 불가 안내**: 이 환경에는 Context7 MCP 서버가 연결되어 있지 않아, 대신 `frontend/package.json`에 명시된 실제 설치 버전(React `^19.2.8`, Vite `^8.3.0`, `react-router` `^8.4.0`)을 기준으로 React/Vite/React Router 공식 문서(react.dev, vite.dev, reactrouter.com)를 WebFetch/WebSearch로 직접 확인했다. 확인 결과와 출처는 문서 하단 각주에 정리했다.
>
> **업데이트 (라우팅 골격 추가)**: 향후 화면 확장에 대비해 `react-router`(v8, 선언적 모드)를 도입했다. `main.jsx`/`App.css`는 변경 없이, `App.jsx` 안에 `BrowserRouter`/`Routes`/`Route`를 선언하는 방식으로 3파일 구조를 유지한 채 라우팅 구조만 추가했다(§3 라이브러리 사용 계획, 각주 [^4] 참고). 실제 코드도 `frontend/src/App.jsx`에 반영되어 있다.

## 1. 컴포넌트/상태 설계

### 1-1. 파일 구조 (고정, 예외 없음)

```
frontend/src/
├── main.jsx   # 엔트리포인트. ReactDOM.createRoot로 App을 렌더링하는 것 외의 로직을 두지 않는다.
├── App.jsx    # 전체 로직 + 마크업. 상태, 이벤트 핸들러, JSX를 모두 이 파일 안에 둔다.
└── App.css    # 전체 스타일. 모든 CSS를 이 한 파일에 작성한다.
```

- 이 3개 파일 구조를 벗어나지 않는다. `components/`, `hooks/`, `utils/` 등 추가 파일·폴더를 만들지 않는다.
- 단, **파일 개수 제한**이지 **함수 개수 제한이 아니므로**, `App.jsx` 내부에 지역 함수형 컴포넌트(예: 메시지 말풍선 하나를 그리는 서브 컴포넌트)나 헬퍼 함수를 여러 개 선언하는 것은 허용한다. 다만 이번 스펙에서는 학습용 단순 구조를 유지하기 위해 서브 컴포넌트 분리 없이 `App` 함수 하나 안에서 조건부 렌더링으로 처리하는 것을 기본안으로 한다.

### 1-2. App.jsx 상태(State) 목록

| state명 | 타입 | 초기값 | 연결되는 UI / 용도 |
|---|---|---|---|
| `models` | `string[]` | `[]` | 좌측 패널 "모델 선택" 드롭다운의 `<option>` 목록. `GET /models` 응답의 `models` 배열로 채워짐 |
| `selectedModel` | `string` | `""` | "모델 선택" 드롭다운의 `value`. `models`가 로드되면 첫 번째 항목으로 자동 설정됨(§2-3 참고) |
| `isModelsLoading` | `boolean` | `true` | 모델 목록 최초 로딩 및 새로고침 아이콘 클릭 시 로딩 상태. 드롭다운/새로고침 아이콘 비활성화 및 로딩 표시에 사용 |
| `systemPrompt` | `string` | `"너는 초보자를 돕는 친절한 AI 강사다."` | "시스템 프롬프트" textarea의 `value` (백엔드 기본값과 동일, PRD §3·§확정1-2) |
| `temperature` | `number` | `0.6` | "Temperature" range input의 `value`, 라벨에 표시되는 숫자 |
| `topP` | `number` | `0.7` | "Top P" range input의 `value`, 라벨에 표시되는 숫자 |
| `numPredict` | `number` | `256` | "Num Predict" number input의 `value` |
| `messages` | `{ id: string, role: 'user' \| 'assistant' \| 'error', content: string }[]` | `[]` | 채팅 메시지 리스트 렌더링. `role`에 따라 정렬(좌/우)·말풍선 색상·마크다운 렌더링 여부가 결정됨 (`error`는 인라인 시스템 에러 메시지, PRD §확정10) |
| `inputValue` | `string` | `""` | 메시지 입력창의 `value` |
| `isSending` | `boolean` | `false` | 전송 버튼 클릭 후 `POST /chat` 응답 대기 상태. 전송 버튼/입력창 비활성화, AI 말풍선 자리에 타이핑 인디케이터 표시(PRD §확정7·9)에 사용 |

**설계 메모**

- 에러 상태를 별도 state(`chatError` 등)로 분리하지 않고 `messages` 배열 안에 `role: 'error'` 항목으로 넣는 방식을 채택했다. 채팅 리스트와 에러 메시지가 같은 흐름(시간순, 스크롤 영역)에 있어야 하므로 하나의 배열로 관리하는 것이 상태 개수를 늘리지 않으면서 §확정10(인라인 에러 메시지)을 그대로 만족시킨다.
- "대화 초기화" 확인 절차(PRD §확정11)는 별도 모달 state 없이 브라우저 내장 `window.confirm()`을 사용한다. 상태를 추가하지 않고도 확인 다이얼로그 요건을 만족하며, 이 프로젝트 규모에 맞는 최소 구현이다.
- 모델 파라미터(`selectedModel`, `systemPrompt`, `temperature`, `topP`, `numPredict`)는 `messages`와 독립적인 state로 유지한다. PRD §4-3에 따라 파라미터 변경은 기존 대화 내용에 영향을 주지 않고, 다음 전송 시점의 값만 요청에 실린다.

## 2. 백엔드 통신 스펙

### 2-1. `POST /chat`

**요청 (Request Body)** — `backend/schema.py`의 `ChatRequest`와 1:1 대응

```json
{
  "message": "FastAPI와 React를 연결하는 이유를 설명해줘.",
  "model": "exaone3.5:7.8b",
  "system_prompt": "너는 초보자를 돕는 친절한 AI 강사다.",
  "temperature": 0.6,
  "top_p": 0.7,
  "num_predict": 256
}
```

| 필드 | 타입 | 비고 |
|---|---|---|
| `message` | string | 필수. 전송 시점의 `inputValue` |
| `model` | string | `selectedModel` |
| `system_prompt` | string | `systemPrompt` |
| `temperature` | number | `0.0 ~ 2.0` |
| `top_p` | number | `0.0 ~ 1.0` |
| `num_predict` | number(int) | `1 ~ 2048` |

**정상 응답 (200)** — `backend/schema.py`의 `ChatResponse`와 1:1 대응

```json
{
  "model": "exaone3.5:7.8b",
  "message": "FastAPI는 백엔드 API 서버 역할을 하고...",
  "elapsed_time": 1.732
}
```

- 스트리밍 응답이 아니다. 백엔드(`ollama_chat.py`의 `call_ollama_chat`)가 Ollama 응답을 완성된 문자열로 받은 뒤 한 번에 반환하므로, 프론트도 `fetch().then(res => res.json())`으로 한 번에 전체 응답을 받아 `messages`에 추가한다(PRD §확정8, §6 성능).
- `elapsed_time`은 이번 UI 스펙에서 화면에 노출하지 않는다(PRD 화면 구성 요소 목록에 해당 표시 항목 없음). 추후 필요 시 메시지 말풍선 하단에 소요 시간을 보조 텍스트로 붙이는 확장은 가능.

**에러 응답 (500)** — `backend/main.py`의 `HTTPException(status_code=500, detail=...)`

```json
{
  "detail": "채팅 처리 중 오류가 발생했습니다: <원인 메시지>"
}
```

- 프론트는 `res.ok`가 `false`이거나 `fetch` 자체가 실패(네트워크 오류)한 경우, `detail` 문자열(또는 자체 안내 문구)을 `messages`에 `role: 'error'` 항목으로 추가한다(PRD §확정10).

### 2-2. `GET /models`

**응답 (200)** — `backend/main.py` → `ollama_chat.get_ollama_models()` 반환값

```json
{
  "models": ["gemma4:e2b", "sageuk-qwen:latest", "llama3.1:latest", "qwen3.5:9b"]
}
```

- 프론트는 `data.models` 배열을 그대로 `models` state에 저장하고, 최초 로드 시 `selectedModel`을 `models[0]`으로 자동 설정한다.
- 모델 목록이 빈 배열이거나 요청이 실패하면(예: Ollama 미실행), 드롭다운은 비활성화하고 "모델 목록을 불러오지 못했습니다" 형태의 안내를 좌측 패널 내에 표시한다(별도 state 추가 없이 `models.length === 0 && !isModelsLoading` 조건으로 판단).
- 호출 시점: (1) 컴포넌트 마운트 시 1회, (2) "새로고침" 아이콘 버튼 클릭 시(PRD §확정6).

## 3. 라이브러리 사용 계획

| 항목 | 결정 | 이유 |
|---|---|---|
| 데이터 페칭 | 브라우저 내장 `fetch` API만 사용. 별도 라이브러리(axios, TanStack Query, SWR 등) 설치하지 않음 | 요청이 `POST /chat`, `GET /models` 두 개뿐이고 캐싱·재검증·페이지네이션 같은 복잡한 요구가 없다. React 공식 문서도 "프레임워크가 없다면 fetch + 상태 관리 또는 가벼운 캐시 라이브러리"를 권장하는데, 이 규모에서는 `fetch` + `useState`만으로 충분하다[^1]. |
| 상태 관리 | React 내장 `useState`만 사용. Redux/Zustand/Context API 등 도입하지 않음 | 상태가 전부 `App.jsx` 한 파일 안에서만 쓰이고 컴포넌트 트리가 깊지 않아(3파일 제한) prop drilling 문제가 발생하지 않는다. |
| 데이터 동기화 훅 | `useEffect`는 **마운트 시 1회 `GET /models` 호출**에만 사용. `use()` 훅(React 19 신규 API)은 도입하지 않음 | React 공식 문서 기준, 사용자 액션(전송 버튼 클릭)으로 트리거되는 요청은 `useEffect`가 아니라 이벤트 핸들러에서 직접 처리해야 한다[^1]. 반대로 컴포넌트가 뜨자마자 필요한 초기 목록 로드는 "외부 시스템과의 동기화"에 해당해 `useEffect`가 적합한 경우로 남아 있다. `use()` 훅은 안정된 Promise와 Suspense/에러 바운더리 구성을 전제로 하는데, 이번 프로젝트는 3파일 제약과 학습용 단순 구조를 우선하므로 Suspense 트리를 새로 구성하지 않는다[^2]. |
| 스트리밍 응답 처리 | 미사용 (`ReadableStream` 등 fetch 스트리밍 API 도입하지 않음) | PRD §확정8·§6에서 백엔드가 완성된 JSON을 한 번에 반환하는 것으로 이미 확정했다. 스트리밍은 §7 제외 범위. |
| 마크다운 렌더링 | **예외적으로 `react-markdown` 1개 패키지 추가 설치** | PRD §3 "AI 응답(마크다운 서식(굵게, 번호 목록) 지원)" 요건이 있는데, 굵게/번호 목록 파싱을 정규식으로 직접 구현하면 엣지 케이스(중첩 목록, 이스케이프 등)에서 쉽게 깨지고 유지보수 비용이 커진다. `react-markdown`은 파일 구조에 영향을 주지 않고(추가 파일 생성 없이 `App.jsx` 안에서 컴포넌트로 바로 사용) AI 메시지 렌더링 부분에만 적용되므로, 3파일 제약과 충돌하지 않는 유일한 예외 의존성으로 둔다. |
| 아이콘/애니메이션(타이핑 인디케이터) | 별도 라이브러리 없이 순수 CSS(`App.css`)로 구현 | 점 3개 바운스 애니메이션은 CSS `@keyframes`만으로 구현 가능한 수준이라 라이브러리가 필요 없다. |
| 라우팅 | **`react-router` (v8, 선언적/Declarative 모드) 추가 설치.** `main.jsx`는 그대로 두고, `App.jsx` 안에서 `BrowserRouter` → `Routes` → `Route`를 선언하는 구조로만 도입. 현재는 `path="/"` 라우트 하나만 채팅 화면(`Home`)에 연결 | PRD 범위상 지금 당장 여러 화면이 필요한 건 아니지만, 향후 화면(설정 페이지 등) 추가에 대비해 라우팅 골격만 미리 마련해 달라는 요구에 따른 것. 프로젝트에 설치된 버전(React `^19.2.8`, Vite `^8.3.0`)이 React Router v8의 최소 요구사항(React 19.2.7+, Vite 7+)을 충족해 v8을 선택했다[^4]. v7부터 `react-router-dom`이 아닌 `react-router` 패키지로 통합되었고, v8에서는 `react-router-dom`이 완전히 제거되었으므로 `react-router`만 설치한다[^4]. "3파일 고정" 제약은 그대로 지키기 위해 새 페이지 파일을 만들지 않고, `App.jsx` 한 파일 안에 화면별 함수형 컴포넌트를 추가하고 `<Route>`만 늘리는 방식을 원칙으로 한다. |

## 각주 (확인 근거)

[^1]: React 공식 문서 [`useEffect – React` (react.dev/reference/react/useEffect)](https://react.dev/reference/react/useEffect). 사용자 이벤트로 트리거되는 요청은 이벤트 핸들러에서 처리하고, "외부 시스템과의 동기화"가 아니라면 Effect를 쓰지 않는 것이 권장된다는 내용을 확인. 설치된 버전(React `^19.2.8`, `frontend/package.json` 기준)에도 동일하게 적용됨.
[^2]: React 19 `use()` 훅 관련 공식/커뮤니티 자료(2025~2026, react.dev 및 관련 해설 자료) 종합 확인. `use()`는 안정된 Promise + Suspense/에러 바운더리 구조를 전제로 하며, 정리(cleanup)나 인라인 에러 처리가 필요한 경우엔 여전히 `useEffect`가 적합하다는 내용을 근거로, 이번 3파일 제약 프로젝트에서는 `useEffect` + 이벤트 핸들러 조합을 유지하기로 결정.
[^3]: Vite 공식 마이그레이션 가이드 [`Migration from v7 | Vite` (vite.dev/guide/migration)](https://vite.dev/guide/migration) 및 [`Vite 8.0 is out!`](https://vite.dev/blog/announcing-vite8) 확인. 설치된 버전(Vite `^8.3.0`)은 번들러가 Rolldown/Oxc 기반으로 전환되었으나, SSR이나 커스텀 번들 설정이 없는 단순 `fetch` 기반 SPA 구조에는 브레이킹 체인지가 없음을 확인. 기본 브라우저 타깃만 상향(Chrome 111+, Edge 111+, Firefox 114+, Safari 16.4+)되었으므로 별도 대응 불필요.
[^4]: React Router 공식 문서 [`Changelog | React Router` (reactrouter.com/changelog)](https://reactrouter.com/changelog) 확인 (Context7 MCP가 이 환경에 연결되어 있지 않아 WebFetch로 공식 문서를 직접 조회). 최신 메이저 버전은 v8(설치 패키지명 `react-router`, `react-router-dom`은 v8에서 제거)이며 최소 요구사항은 React 19.2.7+ / Vite 7+ / Node 22.22.0+. 프레임워크 모드(SSR) 없이 순수 클라이언트 SPA를 만들 때는 `BrowserRouter` + `Routes` + `Route`로 구성하는 선언적(Declarative) 모드를 공식적으로 권장함을 확인하고 그대로 채택.
